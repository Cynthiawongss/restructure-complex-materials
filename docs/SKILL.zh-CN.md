# 复杂资料分类与结构重组

接收别人已经收集或整理的资料，理解原有组织方式，再按照当前使用者的任务重新清理、分类和组织。原整理者能看懂，不代表接手的人也能看懂；难以理解也不代表资料没有价值。保留有用信息，让使用者知道资料是什么、彼此有什么关系、应该从哪里开始。

| 用词 | 指谁 | 什么时候使用 |
|---|---|---|
| 用户 | 提出任务的人 | 描述任务要求 |
| 资料使用者 | 最终查找、理解和使用资料的人 | 判断结构是否好用 |
| 原整理者 | 此前收集或组织资料的人 | 说明原有分类和约定 |

用户和资料使用者可以是同一个人。结构清晰和内容完整需要分别核对。

## 先盘点，再重组

先读取用户提供或授权访问的材料，分清每份资料的实际性质、使用对象、原有分类、主要字段和版本关系。尝试还原原整理者按什么依据组织内容，哪些约定只对其本人明确。把名称或介绍与正文证据分开：产品设想不能直接认定为已上线案例，旧版或核验底稿也不一定是日常查阅入口。

根据任务规模记录：来源、位置或记录标识、内容用途、保留价值、重复关系、缺失与冲突。资料较少可直接在回复中说明，不必强制制作大表。

- “重要”取决于资料使用者的当前任务，注明理由。暂不相关的内容可建议归档，不因看不懂就认定应删除。
- 区分完全重复、部分重合、互补内容、旧版本和冲突；重复出现不等于内容无价值。
- 看不懂的字段先查定义，找不到就标为未知，不凭编号猜测。
- 读取不完整时列明范围，不能对未读到的内容宣称“没有”或“已经全部保留”。

## 按资料使用者的任务建立结构

确定资料使用者要用资料作什么决定或完成什么行动。优先复用原结构中仍然有效的部分，再解释需要调整的地方。先梳理整体结构再展开重组；用户只要框架时，不继续改写全部内容。

| 组织维度 | 解决什么问题 | 例子与处理规则 |
|---|---|---|
| 主分类 | 从哪里找到内容 | 按业务用途找工具，或按交付阶段找项目资料；按当前任务选择依据，不固定一种分类 |
| 属性字段 | 怎样进一步筛选 | 技术、平台、费用、负责人、状态；不要与主分类混排 |
| 过程关系 | 先做什么、后做什么 | 必要时单独列工作流程，不把先后关系当成内容归属 |
| 使用角色 | 不同角色需要看什么 | 业务、执行、维护可用不同入口；按需选文件、数据表或视图，不必复制全部数据 |

同一层级尽量使用同一种分类依据，父子节点表达清楚的归属。跨类内容可选主要入口加辅助标签或交叉引用，不为凑成树而强行扭曲关系。

对分类边界给出简短定义和代表例子。保留原始名称或编号到可追溯字段，阅读入口使用有含义的名称；必要时提供编号解释。

字段过多时，按使用任务安排三种去向：主要入口只显示查找、比较或行动必需的字段；长说明和低频字段放在可展开的详情或关联记录；原字段名、原值与来源留在追溯层。隐藏或移入详情不等于删除。合并同义字段前确认含义、单位和适用范围一致，记录原字段到新字段的对应；“负责人”“联系人”“审批人”不能仅因都是人名就合并。给主要字段写明含义与示例，不强制固定列数。

## 保留细节与来源关系

先给整体结构和阅读顺序，再按需要展开细节。不要以“简洁”为由只保留名称和短摘要，丢掉目标、步骤、限制、来源或原有细分类。

重组时维护内容去向：原记录或段落 → 新位置 → 保留、合并、归档或待确认的处理方式。合并必须保留互补字段；冲突保留来源和差异，不擅自选择一个值。条目总数相同不能证明字段内容完整。

来源中没有明确写出的项目关联、前置条件或负责人，标为“未指定”；如果建议补充，明确是新建议。不要把自己的推断写成原整理者的安排。

用户只要求分析或看方案时，交付方案即可；整理授权不等于可以删除原资料。需要实际更新时，在授权范围内写入并回读检查，按用户指定方式保留原版与版本关系。

## 选择阅读形式

优先沿用用户指定的文档、表格或导图形式。分清文件、数据表和同一数据的不同视图；不默认“一类一文件”或“一类一张表”。

对导图：一个需要独立展开的细分类别建立独立子节点，不用节点内换行冒充层级。深度由内容关系决定，不强制四级。需要继续编辑时区分原生节点、导图文件和展示图片。

对表格：按使用任务安排可见字段与阅读顺序，处理长文本、列宽、行高和编号解释。工具无法完整显示时说明限制，提出符合原意的选择；不擅自改换载体或删掉长内容，也不声称已通过尚未进行的视觉检查。

用户已表达“从左向右”“彩色标签”“每类一个入口”等偏好时可采用；这些是具体任务的展示选择，不是所有用户的通用要求。

## 交付与核对

通常给出：资料性质与范围、推荐阅读入口、重组后的分类结构、关键字段含义，以及内容对应关系或未决问题。按规模缩减，不为简单任务制造多份文件。

交付前分别检查：

| 检查项 | 通过标准 |
|---|---|
| 结构 | 同层分类依据清楚，资料使用者能理解每项的位置和理由 |
| 完整性 | 原资料都有去向，互补字段保留，冲突明确标出 |
| 真实性 | 原资料、推断和建议能够区分 |
| 可用性 | 能从总览进入详情并完成查找或比较，不依赖未解释的缩写或大量逐格点击 |
| 完成状态 | 分别说明方案、文件生成、实际写入、内容核对和显示检查的状态，不笼统宣称全部完成 |

## 使用示例

“使用 restructure-complex-materials，这份工具库是别人整理的，我看不懂。先说明原结构和重复情况，再按业务用途重组，把技术和平台作为属性，保留详细内容。只给方案。”

“把这批项目交接资料整理成业务人员和维护人员都能使用的结构。保留来源和互补说明，标出冲突，不推断原资料没有写的项目关联。”
